# 选题提案 —— 设计研究方法的 AI 重构

《智能设计系统与管理策略》2026 秋季 ｜ 版本 v0.1 ｜ 2026-10-15

> 命题来源：将一种经典设计研究方法重构为「AI 可执行、人可协同」的 Skill，并从中抽象出至少一个 API 候选，
> 产出技术文档与测试报告。

---

## 一、先看清任务：这门课要交出什么

选题不是选一个"听起来高级"的方法，而是选一条 **8 周内能走完的技术路线**。交付链决定了评估维度：

| 周次 | 交付物 | 对选题的约束 |
| --- | --- | --- |
| 第 2 周 | 选题提案（一页） | 方法必须能用一个清晰流程讲完 |
| 第 3 周 | Skill 设计文档 v1.0 | 需要有架构图、交互流、**评估指标**（信度 / 效率 / 有用性） |
| 第 4 周 | MVP 原型 | Vibe Coding 可交付，零编程基础也能推进 |
| 第 6 周 | 测试报告 | 必须有**可量化**的信度、效率、有用性指标 |
| 第 8 周 | 最终交付 | Skill + API + 文档 + 演示视频 + 最终报告 |

**四条硬约束**

1. 2–4 人小组、零编程基础，全程 Vibe Coding（提示词即开发语言）。
2. 必须设计"人机协同节点"，不做全自动黑箱 —— 这是本课程区别于普通 AI 工具作业的核心。
3. 至少封装 1 个 API 候选（判断标准：输入输出明确、无状态、可复用、调用频率高）。
4. 最终评分同时看"工具质量"与"AI 协作效率"。

## 二、选题的 5 把尺子

| 尺子 | 要回答的问题 | 为什么重要 |
| --- | --- | --- |
| 1 方法论内核 | 重构后还是"那个方法"吗？ | 决定设计文档与最终报告的深度 |
| 2 痛点 × AI 增益 | AI 擅长的是不是这个方法的真痛点？ | 决定"重构"是否成立 |
| 3 工程可行性 | 8 周 + 零基础 + Vibe Coding 能交付吗？ | 决定项目是否烂尾 |
| 4 数据与评测 | 输入数据拿得到？测试报告写得出？ | 决定第 6 周能否交差 |
| 5 差异化 | 会撞题吗？演示时有记忆点吗？ | 决定最终展示的得分上限 |

> 经验法则：**痛点在"文本 / 视觉 / 行为的规模化解读"，AI 增益最大；痛点在"人的价值判断"，
> 应该留给人在回路，而不是硬做自动化。**

## 三、六个候选方向

### 候选 01 · 启发式评审助手（Heuristic Review Assistant）

`原型与评估类` ｜ 难度 ★★ ｜ 推荐指数 ★★★★★

**一句话定位**：让 AI 当"初级评估员"——界面截图进，优先级评审报告出。

- **方法内核**：以尼尔森十大启发式原则为审查标准，构建「原则 → 检测 → 描述 → 建议」的审查链；
  对应教材 1.4.2 的**增强模式**：AI 初筛、人做终审。
- **痛点**：专家评审贵且难约；不同评审者结论不一致、信度难保证；每次改版都要重评一遍。
- **Skill 流水线**：截图 / 设计稿 → UI 元素识别 → 逐条原则检测 → 问题定位 + 严重度分级 → 优先级评审报告。
- **人机协同节点**：确认 / 驳回每条 AI 发现、严重度校准、自定义原则集、追问证据（可追溯）。
- **API 候选**：`/api/heuristic-review`（原则 → 问题清单）、`/api/consistency-check`（改版前后一致性对比）。
- **测试评估**：
  - 信度：与 2 位专家的人工评审对照 —— 问题发现率、误报率、严重度一致性；
  - 效率：单稿评审耗时（AI 分钟级 vs 人工小时级）；
  - 有用性：设计师试用后的 SUS 问卷 + 建议采纳率。
- **差异化**：视觉多模态方向，撞题概率低；输入数据零成本（任何 App 截图都是测试样本）；
  "截图进、报告出"的演示最直观。
- **风险与对策**：VLM 可能"幻觉" → 设计**证据锚点**（引用具体的界面元素 / 区域截图）+ 人工确认节点，
  把幻觉变成"可被驳回的建议"。

### 候选 02 · 用户旅程地图自动生成（CJM Generator）

`用户洞察 → 分析综合` ｜ 难度 ★★ ｜ 推荐指数 ★★★★

**一句话定位**：多源数据进，可编辑的旅程 JSON + 情绪曲线出。

- **方法内核**：把访谈、反馈、日志中的行为与情绪，结构化为「阶段 → 触点 → 行为 → 情绪 → 痛点 → 机会点」。
- **痛点**：多源数据手工整理一版旅程要 2–3 天；情绪曲线凭印象、缺证据；旅程图散落白板，难对齐难复用。
- **Skill 流水线**：访谈 / 反馈 / 日志 → 阶段识别 → 触点抽取 → 情绪弧线 → 痛点与机会点 → 旅程 JSON + 可视化。
- **人机协同节点**：阶段命名确认、触点合并 / 拆分、情绪标注修正、机会点评分排序。
- **API 候选**：`/api/journey-json`、`/api/touchpoint-emotion`、`/api/opportunity-suggestion`。
- **测试评估**：与人工绘制旅程对照（阶段 / 触点覆盖率、情绪标注一致性）；出图时间对比（天 → 分钟）；
  产物能否直接导入 Figma / Miro 继续编辑。
- **差异化**：结构化中间产物（JSON Schema）工程化程度最高，API 化最自然；一图讲完全流程。

### 候选 03 · 智能亲和图（AI Affinity Diagram）

`问题定义与分析综合` ｜ 难度 ★★ ｜ 推荐指数 ★★★☆

**一句话定位**：AI 起草分组，研究者拖拽定稿 —— 教材"增强模式"的标准案例。

- **方法内核**：KJ 法的归纳逻辑不变：从大量数据点到主题集群；AI 只承担"语义相似度初稿"，
  分组直觉与命名判断保留给人。
- **痛点**：200+ 张便利贴时认知严重过载；分组反复推倒重来；离群点容易被淹没。
- **Skill 流水线**：数据点导入 → 语义相似度 → 初始分组 + 标签建议 → 人工调整 → 实时反馈与离群点提示。
- **人机协同节点**：AI 起草、人编辑；集群标签确认；离群点仲裁；合并 / 拆分决策。
- **API 候选**：`/api/text-clustering`、`/api/label-suggestion`、`/api/outlier-detection`。
- **测试评估**：与人工分组对照（调整兰德指数 ARI）、标签采纳率；完成时间对比；研究者主观评分。
- **差异化**：方法论最扎实、教程案例最多；**但撞题风险最高** —— 若选，须在交互设计与评估上做出超预期。

### 候选 04 · 数据驱动 Persona 生成器

`用户洞察与研究` ｜ 难度 ★★ ｜ 推荐指数 ★★★☆

**一句话定位**：让角色卡"长"在数据上，而不是拍脑袋。

- **方法内核**：用聚类从真实调研数据中归纳用户类型，再生成角色卡；强调每个特征都有数据证据。
- **痛点**：Persona 常沦为虚构画像，团队不信不用；表格里的细分群体靠肉眼难发现；角色卡更新成本极高。
- **Skill 流水线**：调研数据集导入 → 无监督聚类 → 群体特征提炼 → 角色卡生成（含证据引用）→ 增量更新。
- **人机协同节点**：聚类数确认、特征筛选、角色卡编辑、刻板印象检查。
- **API 候选**：`/api/generate-persona`、`/api/user-segmentation`。
- **测试评估**：聚类质量（轮廓系数）、角色卡"数据证据支撑率"；从数据到角色卡的时间；设计团队可用性评分。
- **差异化**：可加入偏见 / 刻板印象检测（Fairlearn），呼应课程伦理章节，最终报告有讨论深度。

### 候选 05 · 协作式主题分析（Thematic Analysis Copilot）

`问题定义与分析综合` ｜ 难度 ★★★ ｜ 推荐指数 ★★★

**一句话定位**：AI 提编码建议，研究者确认后长成主题网络。

- **方法内核**：遵循主题分析六阶段（Braun & Clarke）与扎根理论编码逻辑；编码体系的**所有权始终在研究者**。
- **痛点**：开放编码逐行进行、极耗时；编码者间信度（Kappa）难保证；主题网络整理与引文例证检索繁琐。
- **Skill 流水线**：访谈文本 → 开放编码建议 → 研究者编辑（合并 / 删除 / 重命名）→ 主题网络 → 一致性检验 + 引文补全。
- **人机协同节点**：编码确认 / 编辑、主题层级讨论、引文补证、一致性复核。
- **API 候选**：`/api/open-coding-assist`、`/api/theme-consistency`、`/api/quote-search`。
- **测试评估**：与人工编码对照 Cohen's Kappa；AI 建议采纳率；编码时间对比；主题覆盖率。
- **差异化**：学术深度最高，测试报告最好写（Kappa 是天然抓手）；但与"访谈智能分析"易重叠，需明确边界。

### 候选 06 · 概念可视化 / 造型探索

`创意生成与概念设计` ｜ 难度 ★★ ｜ 推荐指数 ★★★

**一句话定位**：把"有机、轻盈、安全感"变成可比较的意象图板。

- **方法内核**：设计语义 → 视觉意象的转译；AI 在此是**激发模式**的载体——产出没有对错，只有"是否引发新想法"。
- **痛点**：意象图板搜集、分类耗时；团队对"风格"的理解难对齐；变体迭代（保留形态、改材质比例）重复劳动。
- **Skill 流水线**：语义关键词 + 参考图 → 意象图板生成 → 风格维度自动分组 → 变体迭代 → 图板报告。
- **人机协同节点**：激发模式（不判对错）、挑选与评分、收敛方向控制、变体参数调整。
- **API 候选**：`/api/design-visualization`、`/api/style-exploration`。
- **测试评估**：同一语义多次生成的一致性、风格分组稳定性；图板制作时间；设计师评审（语义契合度 / 新颖度）。
- **差异化**：工业设计背景最契合、视觉演示最"炫"；**但方法论内核偏弱**（更像设计实践），评测偏主观，
  图像 API 成本需计入预算。

## 五、推荐路线

**首选：候选 01 启发式评审助手（24/25）**

1. **评测最"可量化"**：问题发现率 / 误报率 / 严重度一致性，直接喂饱第 6 周测试报告。
2. **数据零成本**：任何 App 截图都是测试样本，可轻松建 20–30 张的评测集（还能让同学扮演"专家"做对照）。
3. **演示最直观**：截图进 → 报告出，3 分钟演示视频无需解释。
4. **差异化**：多数小组会选择文本类方法（访谈、亲和图、问卷），视觉多模态方向稀缺。
5. **与专业背景契合**：交互设计评审能力是工业设计工程研究生的核心能力，最终报告有话可写。

**备选 A：候选 02 旅程地图自动生成** —— 想强化"工程化 + 可视化"叙事时选它；
结构化 JSON 中间产物让 API 化与测试都更顺。

**备选 B：候选 03 智能亲和图** —— 最稳、教程最多、方法论最扎实，但要接受撞题风险。

**暂不建议**：可用性测试视频分析（★★★ 多模态实时处理）、趋势雷达（★★★ 需要长期运行采集）、
文化探针（★★★ 多模态），8 周内烂尾风险过高。

**首要风险与预案**：VLM 幻觉 → 证据锚点（引用界面元素 / 区域）+ 人工确认节点，
把幻觉变成"可被驳回的建议"，这本身就是课程要考察的人机协同设计。
