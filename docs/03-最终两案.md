## 共同的技术底座：用权威规范"喂"出判据

两个方案共用同一套知识来源方式：把 **Apple HIG 等权威设计规范/设计系统文档**作为语料库喂给模型（抓取网页或文档 →
检索 → 引用）。好处有三个：

1. **判据不用自己编**：规范条款本身就是经过验证的设计知识；
2. **输出可溯源**：每条结论都能标注依据（"Apple HIG · Layout"），可解释、可讨论；
3. **评测有抓手**：可以统计"结论中带规范依据的比例"，作为信度之外的特色指标。

## 方案一 · 设计自查助手

`自查与评审` ｜ 难度 ★★ ｜ 推荐指数 ★★★★★

**一句话**：设计目标 + 权威规范 → 判据 → 逐条检查。

- **解决的问题**：自查靠感觉，说不清设计是否服务目标；规范读过但落不到具体界面决策上；
  评审意见零散，改完不知道有没有变好。
- **机制**：
  1. 输入设计目标（一段话）+ 交互稿 → AI 先把目标**结构化**；
  2. 从规范语料库（Apple HIG 等）**检索相关条款**，翻译成可检验判据；
  3. 逐条对照设计稿 → 结论（通过/存疑/未通过）+ 证据（引用界面区域）+ 依据（引用规范条款）；
  4. 输出检查报告与改动建议。
- **人机协同**：确认目标表述 → 确认判据适用性 → 标注"已解决 / 待讨论" → 复审闭环。
- **API**：`/api/objective-to-criteria`（目标 → 判据清单）、`/api/design-check`（判据 → 检查报告）。
- **测试评估**：信度（与资深设计师人工评审对照：召回率 / 误报率）、
  溯源率（结论中给出规范依据的比例）、有用性（已知问题样本集命中率 + 建议采纳率）。
- **适合谁**：想练"从规范 / 理论到具体设计决策"的能力 —— 做这个工具的过程就是训练本身。

## 方案二 · 瞬间可读性与注意力审查

`自查与评审` ｜ 难度 ★★ ｜ 推荐指数 ★★★★★

**一句话**：高压场景里，关键信息能在 0.5 秒内被抓住吗？—— 工具预测 + 真人实验双重验证。

- **解决的问题**：战斗 / 结算界面在高压节奏下是否真的读得清；关键信息埋在密集 HUD 里设计时看不出；
  改版后只能凭感觉说"好像清楚点了"；UI 与特效、伤害数字争夺注意力。
- **机制**：
  1. 输入截图 / 战斗片段 + 设计师标注的关键信息清单；
  2. 结构与注意力两层分析（信息密度、分组、层级、视线焦点、干扰源）；
  3. 输出可读性风险清单 + 优先级 + 改版建议；
  4. **验证闭环**：改版前后各做一次瞬时识别实验（300ms 展示 → 测识别准确率与反应时间）。
- **人机协同**：标注关键信息 → 确认 / 驳回风险点 → 改版前后对比 → 实验数据复核。
- **API**：`/api/glanceability-audit`、`/api/attention-map`。
- **测试评估**：信度（与资深设计师人工审查对照）、**效度（识别准确率 vs 工具预测的相关性）**、
  效率（审查时间对比）。
- **适合谁**：想要最硬的测试数据、最有游戏特色的演示。

## 怎么选

| | 方案一 设计自查助手 | 方案二 瞬间可读性审查 |
| --- | --- | --- |
| 检验的是 | 设计是否服务目标、是否符合规范 | 高压场景下是否真的读得清 |
| 知识来源 | 权威规范库（Apple HIG 等） | 规范库 + 真人实验数据 |
| 最强指标 | 可溯源率 | 效度验证（工具 vs 真人） |
| 个人收获 | 从规范到设计决策的能力 | 实验设计与效度验证的经验 |

**建议**：想做深、最贴个人成长 → 方案一；想评测最硬、演示最出彩 → 方案二。
两者可以串联：v1 先做方案一，v2 把方案二的可读性检查并入同一份"设计体检"报告，
正好对应课程"先做流程技能、再扩展为复合技能"的要求。
