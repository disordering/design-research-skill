# 2026 年 10 月 21 日：四项程序修复说明

本次修改处理 D 首轮检查发现的四个程序问题，方便同学了解改了什么、为什么改，以及怎样复测。说明、注释和后续提交使用中文；接口字段、错误代码和命令保留原名，避免影响程序调用。此前两条英文提交保留，不改写历史。

## 四项修改

| 问题 | 修复前 | 修复后 | 修改位置 |
| --- | --- | --- | --- |
| 模型回复格式错误 | 首次回复不符合要求时，程序可能在发起修复请求前崩溃。部分校验错误也无法转成可传递的文字。 | 及时保存错误说明，正常尝试一次修复；再次失败时返回 `502 / model_contract_failed`，而不是意外崩溃。 | `engine/service.py`：`_request_validated`、`_format_validation_error` |
| 同一判据出现重复问题 | 先出现的低置信度候选可能挤掉后面的高置信度候选。 | 优先保留高置信度候选；相同置信度保留先出现者。较低置信度候选如有独有判据，仍保留对应判据及证据。 | `engine/service.py`：`_normalize` |
| 上传图片像素过多 | 图片库在首次打开图片时产生的异常或警告可能漏接，造成服务器错误。 | 从首次打开起处理超大图片异常，在验证和解码前检查 5000 万像素上限，超限返回 `413 / image_pixel_limit`。 | `engine/imaging.py`：`prepare_image`、`_check_pixel_limit` |
| 上传文字超过长度限制 | 表单上传中的超长文字可能变成服务器错误，无法明确指出出错字段。 | 复用 `ReviewContext` 校验，返回带字段位置的 `422`；仍先去除首尾空白，再判断长度。 | `engine/api.py`：`review_audit_upload` |

## 复测结果与范围

修复后 **48 项全部通过，0 失败、0 跳过**：原有 15 项、首轮回归 8 项、本次补充 25 项。首轮 8 项由“3 通过、5 失败”变为全部通过；这 8 项测试函数内容未变，没有降低断言要求。新增测试覆盖重复候选顺序、相同置信度、长度边界、像素边界及连续两次格式错误等情况。

上述结果来自离线模拟和程序内接口测试，未调用真实模型，也不是真人评审结果；不能据此证明模型判断准确或用户体验良好。测试另有 1 条既有的 Starlette/httpx 依赖弃用提示，不影响通过结果。

## 同学如何复测

先在项目根目录安装 `requirements-dev.txt` 中的依赖，再于 PowerShell 运行：

```powershell
$env:REVIEW_CONFIG = "config/reviewer.example.toml"
python -m pytest -q -p no:cacheprovider
```

这组离线测试不需要填写 API 密钥。复测时同时查看通过数和失败数；真实模型重跑、专家标注及真人测试仍需另行完成。
