3. 将共识整理为唯一具体问题：位置、现象、修改动作、严重度、通用判据/目标、来源和确认记录；未决条目单列。
4. 冻结参考后，再由独立核对者匹配模型发现，保留有效新发现、错误发现、未决及漏检。

若两位无法完成共识，明确降级为“独立选择一致性 + AI 模拟开发对照”，保留不足，不用 AI 代签真人共识。

### T03：真实链路与最小对照

主责 B+D，C 提供端到端执行入口。

- 第一步选 S07 做真实基础链烟测，检查多位置发现和人工干预；再用 P01 检查目标/证据解释。
- 同图至少做 3 次独立真实运行，不能用缓存命中或保存输出回放冒充模型重复运行。
- 最小对照为：同一模型的全量 24 判据基线，与选定的增强方案。固定输入、参考、模型快照及主要采样参数。
- 若资源不足，只做“基线 vs 一个增强方案”；相关性筛选没有实证优势时，保留全量检查为主路径。
- 费用、token、失败、重试、阶段时间与墙钟时间均记录；付费运行留到配置就绪后的实施阶段，本草案不触发调用。

完成标志：真实模式有完整操作日志；不同路径结果分别标注，至少产出一张可复算对照表。无法执行的对照写“未完成”，不把 Codex 历史运行和 Qwen 新运行拼成架构优劣结论。

### T04：真实用户与效率

主责 D+C。

- 建议招募 6–8 位真实工具使用者，按实际角色记录背景；现有一位反馈保留，不把 AI 角色计入人数。
- 任务覆盖上传、理解意见、定位证据、确认/驳回、严重度、反馈、复审与导出；主持人不代操作。
- 记录实时从开始到导出完成的任务时间，包含模型等待、失败和重试；补填记录继续从时间分母排除。
- 用等难度的不同截图比较人工与工具辅助，平衡顺序，避免同图学习造成虚假省时；人工任务也须生成等价评审结果。
- SUS 如选择收集，则使用完整量表单独计分；现有三项 1–5 分不能转换成 SUS。
- P01 五秒识别另作“被评界面”小实验，不混进“明鉴工具体验”。先做题意预试，再用新版本/新轮次测位置与目的；前后采用首次看图者或平衡实验设计。

完成标志：人数、完成率、有效时间分母、评分人数和原话齐全；可以说明真实瓶颈，不能仅展示平均分。

### T05：统一计算口径与发布复现

主责 D，A 确认问题单位。

| 维度 | 建议指标与限制 |
| --- | --- |
| 准确性 | 冻结参考上的问题级 Recall、Precision、F1，另报严重度加权召回；通用判据与目标分别统计 |
| 一致性 | 同一协议逐条状态一致率、具体问题集合相似度与严重度一致率；候选全为空时不把相似度当作有效发现稳定性的证明 |
| 效率 | 人工/辅助的端到端中位数和范围，另报模型等待与阶段耗时；有足够样本再报高分位耗时 |
| 健壮性 | 损坏、超大、裁切、长反馈、超时、格式错误、存储失败；检查错误解释和原记录保留 |
| 体验 | 任务完成、节点误操作、三项实填评分和访谈；SUS 仅在实际收集后汇报 |
| 可解释性 | 作为项目补充维度：出处完整率、证据定位、无证据断言、用户是否理解限定条件 |

终期 PDF 的五维是准确性、一致性、效率、健壮性、体验。我们原来强调的可解释性继续保留，但不能替代健壮性。

计算时：

- 参考问题漏检即 FN，不能因未进 Top-K 就从参考分母删掉。
- “错误发现占比”不是 `FP/(FP+TN)` 意义的假阳性率，报告中明确分母和名称。
- 当前“24 条发现覆盖 25 个参考”的多对多映射不能直接拿两个分母计算标准 F1。先冻结原子问题单位和匹配规则；必要时拆分复合发现，再计算可比 TP/FP/FN。原开发覆盖数据照原口径保留。
- 未决结果与未执行项单列，不当成 TN。多人评价的一致率也不能当模型准确率。
- 在看新结果前确定匹配与严重度规则；不凭现有模拟满分承诺准确性阈值。
