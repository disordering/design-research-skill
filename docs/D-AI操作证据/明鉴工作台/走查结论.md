# 明鉴工作台 AI 演练

2026-11-04，在两个独立的临时 Microsoft Edge 上下文中，分别用快速和细审路径操作明鉴工作台。两轮都从本机载入内置注册截图，使用「模拟演示」。截图上的两个编号和三条初始发现均由演示预设提供。本记录覆盖操作、保存与导出，使用者为 AI。

| 路径 | 审核与判断 | 刷新与导出 |
| --- | --- | --- |
| 快速 | 点击截图编号 2，筛选「高」后只剩字段名称问题。选择「确认问题」，理由是首个输入框只写「请输入」，框外没有可见字段名。 | 刷新后点击同名历史条目，仍为已确认，理由完整。导出显示 `confirmed`。 |
| 细审 | 先筛选「高」和「待审核」，再点截图编号 1。对照示例截图，将「返回」和「确定」使用相同浅色样式的发现由中升为高并确认。字段名称问题记为「待验证」，理由是还需要填写后的画面。 | 从历史重开后两项判断和理由均保留。导出为 `high（原值：medium）`、`confirmed` 和 `verify`。 |

两次刷新都回到新建评审页，需要点击一次历史条目才能继续原评审。细审的双筛选原先仅显示一条发现；点击当时被筛掉的编号 1 后，目标卡片出现在视口内，两项筛选同时回到「全部」，列表恢复为三条。要继续原来的单项列表，需要重新设置两个筛选。[双筛选前](实测/细审/01-双筛选.png) · [编号定位后](实测/细审/02-编号定位后.png)

每轮导出的三条发现都按标题逐一对照，审核状态、等级、理由和原检测说明均一致。快速与细审使用同一演示素材，呈现的是两种审核路径。[快速操作记录](实测/快速/操作记录.json) · [快速原始导出](实测/快速/原始导出.md) · [细审操作记录](实测/细审/操作记录.json) · [细审原始导出](实测/细审/原始导出.md)

可在已安装 Playwright 与 Microsoft Edge 的环境中运行 `python replay.py --out <空目录>`。脚本临时启动只监听本机的静态服务，每条路径创建一个新的浏览器上下文。[复跑脚本](replay.py)
