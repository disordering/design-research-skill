# 回执上写明两处错误，应当命中两个参考

上轮七个评分反例用相同材料重跑，修前 3 项符合预期，修后 7 项全部符合。核对了每个场景的预测、主张内容、证据编号、参考和预期。每次运行新分配的主张编号单列。[输入核对与指纹](对照校验.json)

| 同一份输入 | 修前 | 修后 |
| --- | --- | --- |
| 一条回执意见写明时段和地点都错，两处分别有证据 | 1 个参考命中、1 个漏检 | 2 个参考命中、0 个漏检。预测仍为 1 条，精确率 1/1、召回率 2/2 |
| 只指出时段错 | 命中时段，漏地点 | 命中时段，漏地点 |
| 没选中判据，明确问题仍在冻结参考内 | 漏检 1 项 | 漏检 1 项 |
| 参考与预测均为空 | 两个比率都显示 0 | 各列分母为 0，比率返回 `null`，表示不适用 |
| 一个正确的问题，另加一条分享功能建议 | 预测 2 条，精确率 1/2 | 问题预测 1 条，命中 1 条，功能建议另列 |
| 本版只指出时段，另有过期的地点发现 | 只计本版时段 | 只计本版时段 |
| 都在回执页，一方指出时段错，另一方写加分享按钮 | 自动命中 1 项 | 命中 0 项，两处描述指向不同现象 |

[修前七份输出](修前七项.json) · [修后七份输出与主张编号](修后七项.json)

**批次对照。** 将上轮冻结的七组预测与参考重新读入产品会话，保存并回读，再交给批次评分器。两次输入文件的 SHA-256 相同。修前计为 9 个参考、6 条预测、5 个参考命中。修后为 9 个参考、5 条问题预测、1 条单列建议，4 条预测合计命中 5 个参考。总命中数碰巧相同，逐项结果有两处相反的修正：补回了确有依据的地点错误，同时撤销了“分享按钮”对“时段错误”的误配。[修前批次](修前批次.json) · [修后批次](修后批次.json)

**产品输出。** `session-evaluate` 与 `session-batch-evaluate` 使用 1.1 版结构。`matched` 计参考命中数，`matched_predictions` 计命中参考的问题预测条数，`actual` 计去重问题预测。精确率用命中预测数除以问题预测数，召回率用命中参考数除以参考总数。建议、冲突和重复各有计数。报告有合并表述时，每个参考须能定位到一条独立主张和对应证据。完全重叠的额外预测记入重复，存在其他未匹配主张的重合项另有待核清单。`extra` 表示尚未匹配的预测，语义裁决仍由评审完成。

专项回归另覆盖参考顺序互换、同义重复、复制一条主张试图命中两个参考、引用其他证据、标题与主张不符、部分重合、旧版报告及批次微平均。连同已有的真实会话评分契约共 15 项通过。[专项回归](专项回归.xml)

补充对照还查了“多写几个词会不会多得一次分”。两份预测引用同一张回执、同一对象、同一预期“下午”和观察“上午”。首份标题写“时段错误”，第二份多写“无法核对”。在修复过程中发现，交换编号及顺序的四种排列都会把这一个事实错算为两次命中。最终实现合并两份措辞可支撑的标签，同一事实只提供一个得分位置，四种排列均为命中 1、漏 1、重复预测 1。每个匹配可追到真正写明该标签的原始记录。另给一份预测补上一条未命中字号主张后，四种排列的精确率均为 1/2，部分重合的预测保留待核。[补充核对修前](补充边界修前.json) · [补充核对修后](补充边界修后.json)
