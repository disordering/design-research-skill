## 批次怎么分

- 基线 A 提供入口和任务目的。10 个任务各跑 3 轮，共 30 次。
- 4 个网站另跑 B、C。B 在 A 上加本任务的需求原文。C 在 B 上加对应网站脚本、页面壳、共用逻辑、样式 4 份实现文件，均以“工程实现”角色登记。B 和 C 各 12 次，观察工程材料增量时比较 C 与 B。
- 每个任务、每个条件的第 01 轮预定为该组主指标，共 18 个首轮位置。第 01、02、03 轮一起做一致性分析；每轮重新建会话，使用相同输入、预算、模型及初始状态。失败记录原样保留，额外重试另设编号。
- 模型输入只从原图、指定链接、网站固定任务、服务要求与对应工程文件组装。评审者填写表、现成 D 结论、截图走查记录、程序冒烟答案和打分信息均独立保存。对这批公开任务，可以报告开发回归命中和场景覆盖；用于评价新场景效果时，需另取未向开发或评审模型暴露的任务，让两位真人独立标注、按证据形成参考，并在运行前固定。

## 本地预制请求

工作区 `outputs/D_新版54个请求_开发回归_20261104/` 中，`batch.json` 保存统一配置与指纹，`slots.json` 登记 54 个位置，`requests/` 中每个文件可直接提交给引擎。预制文件沿用项目示例的 `qwen / qwen3.8-max-0902` 配置，只做输入格式校验，不会连接模型。若本轮接入其他可用模型，用该端点的实际模型名生成完整新批次，并保留同一批次的配置。[项目原型请求示例](examples/flex-review-session.json)

在仓库根目录，用已安装引擎 Python 依赖的环境执行以下命令。省略 `--output` 时只校验，指定空目录时保存全部请求；已有批次不会被覆盖。

```powershell
python fixtures/d-v02-batch/prepare.py --provider qwen --model qwen3.8-max-0902 --output out/d-dev-20261104
```

生成器按当前 `SessionCreate` 合约校验并往返解析每份请求，校验 30/12/12 个位置、18 个主指标位、网站材料的递增关系及 15 份源文件指纹。JSON 格式的单轮请求只含引擎字段，条件、轮次、主指标标记、运行状态均在独立的位置表。每份请求的 SHA-256 用排序键、UTF-8 的紧凑 JSON 计算，同一任务与条件三轮具有相同请求指纹。

## 正式执行需要就绪的条件

1. **评分参考。** 两位评审在隔离条件下先各自标注，裁决后冻结参考和任务范围，再开始用于计分的三轮运行。开发调试、浏览器冒烟、Codex 人工操作代测在各自记录中单列。
2. **模型与工具。** 为该版本引擎配置实际可用的模型端点及模型名；本机 Codex 聊天不会自动成为引擎的模型端点。先运行 `python -m engine session-capabilities` 核对浏览器及 Figma 接入。操作者的浏览器可打开画板，与引擎后台身份可读该节点分别验证。
3. **可重复的环境。** 网站服务应与引擎的浏览器运行在同一台机，端口 4311 可达，每轮启用新的浏览器上下文。引擎默认保护内网地址，受控测试进程需要限定在本次本地环境并显式允许访问这些回环站点。画板和原型按既定链接复位，运行前登记真实修订时间或固定快照；文件指纹锁定了本地原图、代码和 URL 规格，线上 Figma 内容需单独核对版本。[网站启动与复位](D-四个网站测试任务.md)
4. **运行及留档。** 每个位置先执行 `python -m engine session-create out/d-dev-20261104/requests/T03-A-01.json`，记下返回的独立会话编号，再执行 `python -m engine session-run <会话编号>`。记录批次、位置、会话编号、实际模型、执行状态、报告版本和耗时。若操作需要授权或访问失败，保存当前状态及原因。完成后将输出交给掌握冻结参考的评价者。[批次评价协议](../方法专家开发交付-v0.2/08-问题表达严重度与评价验收.md#L85)
