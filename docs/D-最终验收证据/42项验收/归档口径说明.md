# 归档口径

- `工程原始轨迹.zip` 保存所有追踪轮，包括夹具预检、QA26 修前失败及修后边界。按 `工程断言最终索引.json` 读取最后有效结果。
- `语义原始轨迹.zip` 保存实际 CLI 提示、线程事件、原答、产品状态和调用记录。`语义最终结果.json` 选取每个场景最终具备完整输入条件的结果。
- “讨论语义两项”原环境记录的调用上限字段写为 2，实际脚本对 QA21、QA22 分别设置最多 4 次，共最多 8 次；该轮实际各调用 3 次，共 6 次。原环境文件保留，本说明更正该元数据，未修改模型原答。后续脚本已统一预算字段。
- CLI 接收的提示使用 LF 换行，Windows 文本归档使用 CRLF。`语义调用索引.json` 同时记录实际输入 SHA256 和归档文件 SHA256；两者各按对应字节核验。
- 工程与语义原始目录经 ZIP CRC 和逐成员 SHA256 校验后，完整迁至仓库外工作目录备份；仓库保留压缩包、每轮汇总、模型原答及关键截图。
- 所有受控输入、故障注入、模拟历史状态和浏览器操作均由 AI 编排。旧体验表的 `D-human-v2.1` 是兼容格式名；QA31 的记录来源以 `QA31-核对结果.json` 中的 AI 验收标注为准。
