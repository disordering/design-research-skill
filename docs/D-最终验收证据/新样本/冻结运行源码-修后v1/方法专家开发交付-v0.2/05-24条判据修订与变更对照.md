# 第5步：24条通用判据修订与逐条对照

日期：2026-10-31。方法草案版本：0.2-method-draft。

## 修订决定

24条全部逐项检查，全部修改执行表述，保留R01—R24、原原则编号和原标题；本轮不拆分、不停用。原因是原库仍承担静态单图基础检查，动态与跨页新能力用独立E方法承接，避免破坏旧编号语义。修改不等于已证明质量提升，需要D按新版本重新测试。

原判据文件与历史运行保持不动。新JSON保留旧CriteriaLibrary的顶层及规则字段，来源链接原样继承，未新增到官方原则中的内容由小组负责。规则详情的上下文、举例和去重信息放独立补充JSON，避免旧模型extra=forbid拒绝加载。

## 统一判定顺序

1. 记录本次材料、对象、状态和版本，执行状态独立于判断状态。
2. 有明确事实证明无适用对象/属于排除情形，判not_applicable；仅没拿到页面不能这样判。
3. 适用性所需关键条件未知，判insufficient_evidence并写缺项。
4. 适用且证据满足触发条件，判candidate_issue。
5. 适用、必要范围已检查且无触发证据，判no_visible_issue。存在已知解释或合理差异通常属于此项，不写成不适用。
6. 尚未执行时decision为空，执行状态标not_executed/blocked/failed；旧接口无法空值时回填须另存执行状态，不能将未检统计成通过或已检查证据不足。

局部有明确问题而其他子项未知时保留问题及未知；没有明确问题但关键子项未知时不以局部通过覆盖未知。各项状态按check_id保存，报告按规则给出候选优先、未知其次的汇总，并列覆盖范围。纯not_applicable才汇总不适用，候选/未知/已检查未见问题的数量分开报告。

R05/R18落实D v1.1的明确条件。G02不并入24条规则，在第8步作为复合目标保留逐子项与汇总规则。

## 逐条完整规格与旧新对照

### R01 当前导航位置可见（H01）

来源：判据库_v1.json:R01。

| 字段 | 原版 | 修订版 |
| --- | --- | --- |
| 适用 | 截图显示页面级导航（如栏目或侧边菜单），且已知这是某一已打开页面 | 已确认当前页面且存在页面级导航。页面内筛选/单选交由R17。 |
| 检查 | 检查当前栏目或菜单项是否有可见选中状态 | 记录当前页面依据，比较页面级导航项及当前项标识；运行模式分别记录跳转前后导航。 |
| 触发 | 多个页面级导航项并列，但无法从截图识别当前项 | 页面级导航及当前页面已知，可完整查看相关导航，但当前项无可辨选中标识或标识与当前页面冲突。 |
| 弃权/排除 | 截图是入口页、页面级导航不可见或不知道当前所在页面；页面内筛选或单选状态由 R17 检查 | 已知是无页面级导航的入口页时不适用；当前页面身份不明、导航被裁切或目标未加载完整时证据不足。 |
| 建议 | 为当前项提供清晰的文字或视觉状态 | 为当前页面提供清楚且与实际位置一致的导航标识。 |

所需上下文/证据：当前页面身份来源；完整导航区域；可选：跳转前后状态。

- no_visible_issue：已确认处于活动页，活动导航高亮，其他项未高亮。
- candidate_issue：已确认进入活动页，但导航仍标记商城。
- insufficient_evidence：只有局部菜单截图，无法确认当前页面。
- not_applicable：已明确不存在本条适用对象或满足本条明确排除条件，记录具体事实；缺材料不能代替不适用。

去重/边界：与R17按导航层级区分；同一跳转失配若同时触发E01，按同一现象归并。

### R02 多步骤任务显示当前步骤（H01）

来源：判据库_v1.json:R02。

| 字段 | 原版 | 修订版 |
| --- | --- | --- |
| 适用 | 截图明确显示注册、结算、申请等多步骤任务的一步 | 已由流程说明或实际路径确认是多步骤任务，当前页属于其中一步。 |
| 检查 | 检查页面是否说明当前步骤或剩余步骤 | 记录步骤关系、当前步骤与可见进度线索，结合标题和上下文判断当前环节是否可辨。 |
| 触发 | 存在多步骤流程线索，但当前步骤不可辨认 | 多步骤与当前位置已确认，但相关区域完整可查时仍无法从标题、进度或上下文辨认当前环节。 |
| 弃权/排除 | 无法确认任务是多步骤，或只看到独立单页 | 已确认独立单页时不适用；仅见一页且无法确认步骤关系，或进度区域未取得时证据不足。 |
| 建议 | 标出当前步骤，并在合适时展示流程进度 | 提供符合任务需要的当前步骤或进度线索，不强制所有流程使用进度条。 |

所需上下文/证据：步骤关系来源；当前页或状态；标题/进度/上下文。

- no_visible_issue：三步申请中，标题写明“第二步：核对资料”。
- candidate_issue：已确认三步申请，但各步同名且没有其他当前步骤线索。
- insufficient_evidence：只有一个表单页，不知道是否属于多步骤。
- not_applicable：已明确不存在本条适用对象或满足本条明确排除条件，记录具体事实；缺材料不能代替不适用。

去重/边界：R02检查当前位置表达；E01检查路径能否衔接，不因同处一流程自动合并。

### R03 等待状态说明系统正在做什么（H01）

来源：判据库_v1.json:R03。

| 字段 | 原版 | 修订版 |
| --- | --- | --- |
| 适用 | 截图已经呈现加载、上传、处理中等等待状态 | 当前取得的画面已经呈现加载、上传或处理中等等待状态；可来自截图、原型或运行记录。 |
| 检查 | 检查等待状态是否有可读的状态说明或进度线索 | 记录等待对象、可见文案与进度线索；运行时记录触发动作、观察时长及前后状态。 |
| 触发 | 仅有模糊转圈或空白覆盖，用户难以知道正在处理什么 | 已确认处于等待，完整相关区域仅有无法解释的转圈/空白，结合上下文仍不能判断正在处理的任务。 |
| 弃权/排除 | 普通页面截图，没有等待状态；无法据此推断点击后是否有反馈 | 已确认普通非等待状态时不适用；无法确认等待状态、区域不全或动作结果未取得时证据不足；不能由点击前截图推断无反馈。 |
| 建议 | 说明正在处理的任务；耗时较长时提供进度或预计等待线索 | 说明正在处理的任务，确有依据时提供进度或等待线索。 |

所需上下文/证据：等待状态依据；等待区域；运行时动作和观察时长。

- no_visible_issue：画面显示“正在载入角色试用”。
- candidate_issue：已确认上传中，整屏仅空白遮罩且无处理对象线索。
- insufficient_evidence：仅有点击前按钮，没有点击后画面。
- not_applicable：已明确不存在本条适用对象或满足本条明确排除条件，记录具体事实；缺材料不能代替不适用。

去重/边界：E03负责是否出现状态变化，R03负责已出现等待状态的说明；同一无反馈现象仅记一次。

### R04 完成状态说清结果（H01）

来源：判据库_v1.json:R04。

| 字段 | 原版 | 修订版 |
| --- | --- | --- |
| 适用 | 截图已经呈现提交、保存、支付等操作后的成功状态 | 已取得某次操作完成/成功状态，完成对象与上下文可确认。 |
| 检查 | 检查成功提示是否说明完成的对象和下一步 | 检查成功表达是否能说明已完成的动作、对象及确有必要的后续操作。 |
| 触发 | 只有笼统的“成功”而无法识别完成了什么 | 完成状态已确认，但只有泛化成功信息，结合上下文仍无法判断完成了什么，或遗漏任务必需的下一步线索。 |
| 弃权/排除 | 截图不是成功状态，或缺少操作前后上下文 | 明确非完成状态时不适用；只有完成前画面、对象不明或结果区域缺失时证据不足；没有后续任务不要求强加下一步。 |
| 建议 | 在成功信息中写明完成的动作、对象及必要的下一步 | 在完成反馈中说明动作与对象，并按任务需要提供后续入口。 |

所需上下文/证据：完成状态画面；动作和对象来源；后续任务要求（若有）。

- no_visible_issue：保存后显示“角色配置已保存”，无需额外操作。
- candidate_issue：同页含多个提交对象，操作后只弹“成功”且无法关联对象。
- insufficient_evidence：代码含成功提示但未取得实际运行完成画面。
- not_applicable：已明确不存在本条适用对象或满足本条明确排除条件，记录具体事实；缺材料不能代替不适用。

去重/边界：结果表达归R04，底层业务完成需独立证据；与E03同现象时合并引用。

### R05 关键文案避免未解释的内部术语（H02）

来源：判据库_v1.json:R05；docs/D-测试判定说明-v1.1.md:R05。

| 字段 | 原版 | 修订版 |
| --- | --- | --- |
| 适用 | 已知目标用户不是该领域专家，且截图中有非错误状态的关键任务文案 | 已确认非领域专家用户，存在非错误状态的关键任务文案；错误文案转R23。 |
| 检查 | 寻找产品内部缩写、代码或术语是否直接替代用户熟悉的词 | 逐词记录任务必要性、内部术语含义来源、目标用户熟悉度依据与可见解释；词表只能证明含义，不能证明熟悉度。 |
| 触发 | 完成主要任务必须理解未解释的内部术语 | 有依据确认非专家完成主任务必须理解某内部术语，该用户群不熟悉该词，界面又未解释。 |
| 弃权/排除 | 目标用户或术语含义不明；该术语可能是目标用户熟悉的专业用语；错误提示中的术语由 R23 检查 | 明确没有相关对象或目标用户为领域专家时不适用；用户、含义、必要性或熟悉度影响结论却未知时证据不足。已解释/有熟悉依据时不能报问题。 |
| 建议 | 使用目标用户熟悉的词，或在首次出现处给出简短解释 | 对任务必需且有理解障碍证据的术语使用熟悉词或提供就近解释。 |

所需上下文/证据：用户与专业程度来源；术语原文/含义来源；任务必要性；熟悉度或解释证据。

- no_visible_issue：非专家需按定位选择角色，旁边写明“强攻：以直接伤害为主”。
- candidate_issue：选择任务必须理解内部定位码，目标用户测试显示不理解，页面无解释。
- insufficient_evidence：只知“中轻度玩家”，未证明是否必须理解“强攻”或是否熟悉。
- not_applicable：已明确不存在本条适用对象或满足本条明确排除条件，记录具体事实；缺材料不能代替不适用。

去重/边界：非错误任务术语用R05；错误提示用R23；术语解释与帮助缺失同一改动可关联R24合并。

### R06 操作名称说明预期结果（H02）

来源：判据库_v1.json:R06。

| 字段 | 原版 | 修订版 |
| --- | --- | --- |
| 适用 | 截图中有主要按钮或操作入口，且任务目标已知 | 当前状态有主要按钮/入口，用户任务和动作目的已知。 |
| 检查 | 检查按钮文字是否足以区分操作目的，例如保存、继续、提交 | 核对按钮文字、邻近内容与预期动作；运行结果可用于确认动作，但不能替代文案清晰度检查。 |
| 触发 | 主要按钮只有“确定”“处理”等泛词，无法结合周围内容理解将发生什么 | 主要按钮使用泛词或含义不符，结合邻近说明仍不能理解预期结果，或与明确动作目的冲突。 |
| 弃权/排除 | 按钮附近上下文已经清楚，或无法知道用户正在做的任务 | 无主操作对象时不适用；任务/动作目的不明或上下文缺失时证据不足；周围内容已清楚说明时，泛词本身不构成问题。 |
| 建议 | 用简短的动词和对象说明操作结果 | 用简短且符合实际动作的名称说明结果，必要时补充邻近说明。 |

所需上下文/证据：任务与动作目的；按钮原文；邻近说明。

- no_visible_issue：弹窗写“删除角色配置？”，按钮“确定”与“取消”含义明确。
- candidate_issue：同页有多个业务对象，主按钮仅写“处理”，无任何动作说明。
- insufficient_evidence：只见一个“确定”按钮，任务说明和弹窗正文都被裁掉。
- not_applicable：已明确不存在本条适用对象或满足本条明确排除条件，记录具体事实；缺材料不能代替不适用。

去重/边界：名称是否说明结果用R06；同一动作跨入口命名一致用R11，同一修改解决时可合并。
