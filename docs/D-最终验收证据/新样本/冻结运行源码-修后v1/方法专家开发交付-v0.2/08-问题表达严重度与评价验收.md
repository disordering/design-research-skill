# 第8步：问题表达、严重度、评价与验收

版本：0.2-method-draft。本稿确定方法与待执行验收，不含新增模型运行或真人实验结果。保持旧接口critical/high/medium/low四级，纠正前期构想只列三级的遗漏。

## 1. 结论类型与报告结构

| 类型 | 输出条件 | 统计 |
| --- | --- | --- |
| 候选交互问题 | R/E01—E06适用且触发条件有支持证据 | 去重后的候选问题；另报各判据检查状态 |
| 目标/需求不符合项 | 已确认G/REQ要求及违反证据 | 目标/需求维度单列，可关联同一finding |
| 材料/要求冲突 | E08存在可定位相互矛盾陈述 | conflict清单，不自动作为产品缺陷 |
| 改进建议 | 尚无足够违规依据但有可讨论方向 | suggestion，不计TP/FP问题数 |
| 未决项 | 缺材料、权限、事实、业务裁决等 | unresolved，注明需要什么和影响范围 |

一个报告包含任务与版本、材料与证据模式、实际检查范围、逐项状态、去重发现、冲突与未决、人工决定、复审、时间及限制。不能把R/E/G条数直接相加算产品通过率。

### 候选问题字段

finding_id、finding_kind、title、task/page/state/transition、related_check_ids、rule_ids/method_ids/goal_ids/requirement_ids、criteria_version、context/material_versions、evidence_ids、principle、detection、description、suggestion、model_severity、severity_reason、model_confidence（可为空）、review_status、human_severity、reviewer/actor_type、review_time、review_reason。

principle写确切依据与适用理由；detection写观察与定位；description分开记录已观察后果和推测风险；suggestion写可执行修改/补证，不擅自生成新业务规则。置信度不是准确率，严重度不是置信度；程序校验与模型核验分开。

### 四段式例子（合成说明）

- 原则：E04及本项目REQ-03规定返回难度选择后保留已选角色。
- 检测：测试版本v2中选择角色A后进入难度页，再点返回，画面显示角色B；关联EV-01、EV-02及ACT-01。
- 描述：本次选择在返回后改变，可能使用户试用非预期角色；尚未证明所有账号均受影响。
- 建议：修正返回时角色状态恢复，复测A/B角色和相关返回路径。

没有真实材料时不生成带虚假URL/截图框的“示范实测报告”。

## 2. 严重度规则

| 等级 | 本项目判定标准 | 例子（假设） |
| --- | --- | --- |
| critical 严重 | 有充分证据表明发生不可逆或重大业务损失，或所有既定关键路径均被阻断且无可用替代；需记录影响范围和可恢复性 | 受控测试明确证明高后果误执行或核心任务全路径不可恢复阻断 |
| high 高 | 关键任务/分支明确无法完成，或严重错误结果，无合理可用替代；影响未达到critical证据要求 | 核心试用路径稳定到达错误对象，无法继续目标任务 |
| medium 中 | 增加明显理解/操作成本或局部任务受阻，但有可用替代/恢复路径 | 已知必要格式没有提示，出错后仍可按清楚指引修正 |
| low 低 | 有证据支持的局部表达/一致性问题，对任务影响有限且易恢复 | 同一辅助动作命名不一致但上下文仍可理解 |

分级必须写任务重要性、阻断程度、影响范围、替代/恢复方式及证据。未知后果不能当已发生损失；信息不足可保留候选等级和待验证项，不把所有未知一律低级，也不因潜在风险大就自动critical。频率无样本则unknown，不编造“经常”。

人工调整需理由，保留原等级。接受某项设计取舍不等于事实已改变；可确认存在并接受风险，review_status与disposition（fix/accept_risk/defer）分别记录。

## 3. 去重、冲突与复合目标

去重依据为同一版本/语境、同一对象与位置、同一具体机制、同一修改动作。满足时合并finding并保留全部依据；不同页面同组件机制且同一改动可解决时一条列多位置。仅判据相同不合并，独立对象/机制或需独立修改则分开。每个检查项仍保留自身状态。

需求与意见冲突先建立CON编号，记录双方原文、角色、版本、影响和可选取舍；有权用户裁决后保存决定并重查。不能默认最新文件/开发实现/声音更大的一方正确。冲突解决前不声称整体符合。

G02等复合目标先拆子项：任一observed_violation则整体observed_violation；否则任一insufficient_evidence则整体insufficient_evidence；否则全部met才整体met。模型新增阈值如90%重合、4.5:1、100ms等不能直接当已确认项目标准；原文已有规范要求才按其范围检查。布局/显著性代理不替代真实理解或行为效果。

## 4. 评价计划：主指标与统计单位

评价结果按入口、证据模式、版本、用户来源分组。工程契约通过、模型判断正确、真人体验改善分别报告。

| 维度 | 主指标与公式 | 执行要求 |
| --- | --- | --- |
| 准确性 | 召回率TP_ref/(TP_ref+FN_ref)；错误发现占比FP_pred/N_pred_adjudicated，即FDR | ref按冻结参考原子，pred按已裁决去重预测；下述匹配规则处理一对多 |
| 一致性 | 固定check_id三次状态完全相同比例 | 固定材料、上下文、判据和配置；另报执行覆盖，避免都未执行带来高一致 |
| 可解释性 | 来源/定位/四段式均完整的意见占比；证据实际支持判断的意见占比 | 结构完整与语义支持分别人工核对 |
| 效率 | 用户完成任务的端到端耗时、活跃操作时间、AI/工具等待时间 | 同任务条件对照并记录中断；模型阶段求和不替代真人计时 |
| 体验 | 理解意见、找到证据、完成审核保存的1—5分与任务完成率 | 实际使用后采集；报告人数、分布和原话；AI角色单列 |
| 健壮性（补充终期要求） | 异常/恢复用例通过数、上下文与版本正确保留数 | 工具失败、权限、刷新、重复事件、过期证据、错误引用等 |
| 协作质量（补充） | 必要澄清覆盖、可避免提问占比、变更重查正确率、无依据迎合次数 | 参考答案预先冻结；正常用户澄清不视为泄漏答案 |

### 参考与匹配

两名真实评审独立标注后形成带证据的共识参考；仍有分歧的项单列ambiguous，不进确定参考主分母，但记录其数量与原因，禁止看见模型结果后为提高分数改分母。AI可以辅助整理，不把AI模拟共识标真人共识。D的隔离参考不得输入评审模型。

匹配需同对象/位置、同现象机制、对应任务条件，不仅同规则号。先去重，再建预测—参考映射。一个合理归并的模型发现可覆盖多个参考原子问题，若每个原子都有实质描述与证据，则各参考计检出；预测错误占比按预测条目计算，因此分别报告“参考问题命中数”和“模型预测条目数”，不强求两个TP计数相同。部分覆盖只命中明确表达的参考原子。重复预测的额外条目不增加召回，单列重复率，不自动等同错误事实。

FDR使用“含至少一条无支持问题主张的预测条目/已裁决去重预测条目”；正确与错误混合的条目计错误条目并保留原子明细。这里N_pred_adjudicated是已裁决条目数；全正确条目与错误条目构成该分母，与按参考原子计数的TP_ref不同。无法裁决预测单列pending，不假装FP=0；主结果注明已裁决比例，并报告把pending均视错的保守FDR=(FP_pred+N_pending)/(N_pred_adjudicated+N_pending)。召回主分母冻结；参考已明确的问题即使其判据未进Top-K仍计FN，不因系统弃权排除。

分母为0写N/A并给计数。报告通用R、流程E、目标G/REQ的分层命中，跨类别同一问题在总体按唯一原子去重；conflict和suggestion另行评价。

### 一致性与证据指标口径

预先冻结应比较check_id清单；未执行项仍留在清单并计覆盖未完成，主“判断一致率”分母只含三轮均已执行且结论可比的项，同时必报共同执行覆盖率，不能只展示高一致率。目标和通用规则分开统计。按需补充全部计划项的状态一致率，标签写明包含执行状态。

证据完整率分母为全部去重候选问题；缺来源/定位/四段式任一不计完整。语义支持率由真实评审判断是否足以支持该结论，未裁决单列并给保守下界。不把文件哈希、非stub或JSON合法当准确证据。

## 5. 样本与执行安排

冻结10个开发测试任务：2个单图/静态、4个可操作网站、2个Figma画板、2个Figma原型。现有角色试用页用于静态旧能力回归；新网站/原型及文档由B/C/D建立受控材料，未建立前标fixture_not_ready，不声称已存在。可复用既有S03/S07材料作缺陷回归，复用前核对版本与适用性。

每任务在固定条件下独立运行3次，共30次基线计划；主准确性预先指定第1次，三次结果全报范围并作一致性分析，不能挑最好一次。工具调用、环境状态和目标条件冻结，网站每轮恢复初始状态；存在非确定数据时记录并限制比较。

另安排6位真实目标使用者，每人完成匹配难度的人工与工具辅助任务，用交叉顺序降低先后学习影响。记录设备、任务、时点和中断；人数不足如实标，不以AI角色补足真人数量。若不能取得人工基线，只报工具耗时，不算效率提升。

## 6. 回答老师的源文件效果问题

在4个网站任务上设置三种独立条件，网站版本、任务和模型配置固定：A=网站+目的；B=A+需求/策划文档；C=B+相关工程文件。每条件3次独立上下文，A复用上述基线；额外B/C共24次计划。总计划54次，不含失败重试和真人任务。

比较共同可观察问题的检出/FDR、全任务需求覆盖、材料冲突识别、无依据推断、运行时间与澄清成本。需求专属问题单列，避免把更多输入信息解释成纯模型能力提升。C相对B才用于观察工程文件增量，不把文档和源码混在一个因素。每条件都不能获取D参考；对源码含而运行未生效的状态设专门反例。测试范围小，结果只支持该任务集，不能宣称普遍提升。
