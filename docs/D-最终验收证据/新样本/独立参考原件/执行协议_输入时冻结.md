# 新样本独立验收：预先冻结的执行与统计约定

本批使用 N01 阅读设置、N02 器材借用清单、N03 图书编目录入三个新建本地交互任务，材料版本均为 v1。样本由 AI 制作；任务操作与模型评审由 AI 执行；独立参考采用另一 AI 对原始浏览器事实的独立审阅。三类来源分别记录。

## 固定输入与生产链路

运行模型只获得当前任务入口和对应冻结任务卡。作者的样本实现、独立参考答案、独立取证包和其他轮次结果均不进入评审模型输入。独立参考先于评审模型运行冻结在仓库外的 work 目录。运行脚本只读不含答案的冻结回执。

使用 main 66a0f0919ada6d334565c3451e9f16ea95000bc9 的生产源码字节快照，存于冻结运行源码。通过生产 SessionService、BrowserAdapter 和原生产逐屏 review 方法执行。客户端在测试实例中接入真实 Codex CLI；原提示、schema、像素指标、校验及报告导出逻辑保留。调用输入、原答、线程、用量分别留档。

每项运行三轮，每轮为全新会话、状态库和浏览器上下文。先执行 N01 第 1 轮试点并记录调用量，再推进其余轮次。每轮上限：100 次模型调用、24 个动作、160 个检查、120 分钟、1 轮缺证追查，逐屏并发为 1。达到上限的覆盖保持未执行或证据不足。产品正常规划全量执行，不预填判断或删减判据以保证通过。

## 预先固定的可比任务单位

| 任务 | 任务卡要求 | 需对齐的状态与转移 |
|---|---|---|
| N01 | REQ-N01-01 / 02 / 03 | 初始→选择完成→应用响应→应用完成→恢复后 |
| N02 | REQ-N02-01 / 02 / 03 | 初始→数量选择→首次清单→修改后清单 |
| N03 | REQ-N03-01 / 02 / 03 | 初始→无效年份填写→首次保存响应→修正年份→再次保存→必要补填及保存 |

每轮保留生产动态 check_id / coverage_id 原文。跨轮映射按固定要求编号、对象、任务条件与实际状态/转移完成；不能唯一映射的项单列不可比，并保留覆盖缺口。上述 9 条要求为固定业务要求分母；模型新增的判据覆盖另列，不把三轮不同的动态检查总数相除。

## 准确性与一致性

第 1 轮为预先指定的主准确性结果，第 2、3 轮用于重复性分析；不从三个结果中挑最好一轮。参考问题以“同对象/位置＋同现象机制＋任务条件”为原子单位。未执行而漏掉的参考问题仍计漏报。

候选按原子问题去重。一个候选若含至少一条无证据支持的实质主张，计入错误发现。逐屏候选、任务级最终发现分别列原始计数，匹配同一原子问题后才能合并，不能直接相加。

重复性同时报告三轮共同执行的可比要求范围、判定一致性、发现的一致性与覆盖缺口。“证据不足”按独立状态保留，不归为通过。无法取得独立参考的内容只记录观察，不补造准确性分母。

## 版本与新问题

材料冻结后不根据模型结果改题或改参考。若发现产品程序问题，先保留原版实际记录，另开修后批次并记录源码版本；不同产品版本不混为同一三轮一致性数据。
