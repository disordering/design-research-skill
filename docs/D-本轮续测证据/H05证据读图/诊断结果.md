# H05 提交前后证据读图诊断

两组截图各运行了 3 个独立 Codex CLI 会话。A 的 3 次回答都指出回执时段与服务台错配，并判为高严重度。B 的 3 次回答都判断最终核对与完成页一致，没有报告该问题。六次引用的图号、时段与服务台均与输入截图相符。

| 图片组 | 第1次 | 第2次 | 第3次 | 核对依据 |
| --- | --- | --- | --- | --- |
| 图组01，原题 A | 要求3受阻，高 | 要求3受阻，高 | 要求3受阻，高 | 图1为14:00–14:30、二层服务台；图2为09:00–09:30、一层服务台 |
| 图组02，D制作的对照 B | 要求3达成，无问题 | 要求3达成，无问题 | 要求3达成，无问题 | 图1、图2均为14:00–14:30、二层服务台 |

两组内部的三次要求状态完全一致。对于要求1“选择页同时展示时段与服务台并可更换”和要求2“返回后保留选择”，六次均回答“证据不足”，并把严重度记为“待定”。本次只给末次核对页和完成页，没有给返回后的选中状态截图。模型没有把未展示的选择页写成已观察事实。

逐条核对六份原答，未发现虚构时段、服务台、图号或选择控件的事实幻觉，也没有发现声称由模型亲自执行浏览器操作的表述。B 组没有出现目标错配误报。原答中的“无法排除重新选择”用于说明缺少的证据，并未当作已发生操作。

## 本次怎么跑

- 模型为 `gpt-6-astra`，推理设置为 `low`，共 6 个独立线程，每个线程只接收一组图片。
- 使用已有 Chromium 走查保存的原尺寸 PNG，直接复制，字节指纹相同。
- 输入为任务卡原文、两张图片及同一段中性路径“选择下午二层服务台 → 核对信息 → 返回选择 → 核对信息 → 提交登记”。图片文件名统一为 `frame-01.png`、`frame-02.png`。
- 模型没有收到 A/B 映射、预期答案、实现代码或修复说明。两组的完整提示词相同，提交前核对图也相同，完成页截图呈现各自结果。
- CLI 使用独立临时目录和 `--ephemeral`，关闭 shell、浏览器、插件、应用、子代理等工具入口。原始事件复核确认额外工具调用为 0。
- 评分预期在运行前从真实浏览器的冻结记录生成。该预期只提供给事后复核，不提供给模型。

这组结果说明，给出清晰的提交前后证据时，当前模型能在本题重复区分目标错配与正确回执。本次诊断位于“已有证据的图像判断”层，未执行产品的原生采集、规划、判据匹配和复审结案流程。后续可把产品实际交给模型的材料与这组输入逐项对齐，检查差异出现在采集、传递还是判断环节。

B 是 D 为本题制作的修正版对照样本。此处记录的是 AI 证据读图诊断，结果按本题的 3 次重复分别报告。

## 证据位置

- [输入索引](输入索引.json) 保存任务卡、完整提示词、原图与输入图的 SHA-256。
- [输入字节复核](输入字节复核.json) 对照 Windows 文本换行与实际 CLI 标准输入字节，六次实际输入指纹相同；原样字节保存在 `输入/实际标准输入.txt`。
- [冻结评分口径](冻结评分口径.json) 保存本题预期及浏览器记录指纹。
- [有效调用汇总](有效调用汇总.json) 保存 6 个线程 ID、模型设置、工具项、时间和成功状态。
- `原始会话/` 保存每次 CLI 的原始 JSONL、标准错误、未经改写的模型原答和解析复核记录。
- [逐条复核结果](逐条复核结果.json) 保存每次目标判断、引用核对与幻觉检查结果。复核执行者为 Codex AI。
- `评分依据/四组浏览器走查.json` 为已有浏览器记录的原样副本，仅供评分复核。

采集器最初把“code-mode host 已禁用”的启动通知归入工具项，误标调用失败。原始 JSONL 中六次均退出码 0、正常 `turn.completed` 并带完整回答。初次记录完整保留，`解析复核.json` 与 `有效调用汇总.json` 按事件类型纠正状态。本次实际模型调用总数仍为 6，没有为修正采集状态而重跑模型。

`运行诊断.py` 保存具体调用参数和提示词构造。已有输入与原答禁止覆盖，新的实验应使用独立目录保存。
