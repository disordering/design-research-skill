# H05 原生评审调用效率诊断

记录日期：2026-11-04。执行者：Codex（AI 代码与记录复核）。

本记录固定检查 `03-A初审/调用/001-understand` 至 `018-plan_checks` 的已返回记录及对应生产代码，是交给 B 的后续优化建议。本轮继续使用现有语义完成前后对照；调用慢、调用次数多本身不记为产品判断错误。以下数字属于这段执行记录，不是整轮最终统计。

## 哪些重查确有新证据

H05 在这段记录中完成了四次点击：更换时段与服务台、进入核对页、返回选择页、再次进入核对页。后两步用于检验返回后是否保留选择，操作发生顺序及每次观察都应保留。第 015 次调用规划提交登记，随后进入提交前授权流程；这里不把规划当成提交已完成。

第 002—006 次 `plan_checks` 是 35 个不同检查编号的初次分批，每批最多 8 个，是正常覆盖规划。四次点击后产生了新的页面状态与操作证据，重新规划受影响的返回、状态保留及提交检查有明确用途。

## 可复用的内容在哪里

### 1. 正式要求未变，材料理解重复执行了五次

第 001、008、010、012、014 次均执行 `understand`，`context_version` 均为 1，正式任务材料和初始委托的证据编号没有变化。五份输出中的三条要求原文相同：

- REQ1：选择时同时显示时段和服务台，并允许用户更换选择。
- REQ2：从核对页返回选择页时，保留上一次选择的时段和服务台。
- REQ3：提交后，完成页显示用户最终确认的时段和服务台。

生产代码 `_understand_materials` 以“上下文版本相同，且当前材料证据编号已全部理解过”为缓存命中条件。`_capture` 优先使用材料角色，H05 网页的 `role=design` 使连续网页截图成为 `kind=design`；`_understanding_evidence` 排除的是 `observation`，因此这些截图持续进入材料集合。每个新证据编号都会触发整份材料重理解，并清空检查规划指纹。

本段共有 5 条界面证据、3 个不同状态：初始选择页、更换后的选择页、核对页。返回和再次核对分别复现后两个状态。新发生时点支持返回验证，同一状态内容则可复用。任务说明的措辞在重理解中有调整，不能据此说全部输出完全相同；可以确认的是上述正式要求没有变化。

### 2. 第二轮规划把已展开的覆盖项再次当作输入行

`_plan_checks` 使用有效证据编号、上下文版本、完整目标与要求、任务以及页面状态生成指纹。新观察出现后指纹变化，当前所有 `CheckItem` 再按 8 行分批。这时一个 `ref` 已展开为多个 `coverage_id`。

实际第 016 次输入中 E07 连续出现 3 次；E01 又跨第 016、017 次出现。送入模型的每一行只有 `ref`、`kind`、`spec`，不含该行的 `coverage_id`。生产 `_apply_check_plan` 的模板字典按 `ref` 选取，输出写回则按 `(ref, coverage_id)` 匹配。也就是说，当前输入中的重复行没有靠覆盖编号向模型消歧，最终覆盖仍由模型输出决定。

这支持按检查编号组织下一版输入，但还不能直接认定删去重复行后的随机模型输出等价。优化时应将同一编号已有的覆盖清单显式汇总，并验证覆盖数量、引用及目标完整性。

### 3. 重复状态的完整结构和图片反复进入上下文

第 018 次调用记录实际输入为 **67,138 tokens**，其中记录的缓存输入为 **12,416 tokens**。按原始输入 JSON 重新序列化计算，其 `context` 约 **84,315 字符**，其中 `evidence` 约 **46,215 字符**；主要体积来自对象、定位及分析结构。字符数用于定位请求体积，不能当作 token 数。

该次传入 5 张图片，图片 SHA-256 只有 3 个不同值，符合“返回选择页、再次核对”的状态重复。发生时点和证据编号有用途，完整重复状态结构与图片可以建立规范副本引用。

## 给 B 的三项后续改进与验收条件

| 优先级 | 改进 | 可验收结果 |
| --- | --- | --- |
| 1 | 分开缓存正式材料理解和运行中的状态理解。正式要求按材料内容、版本及目标更新失效，页面变化增量更新任务与证据关系。 | 在同一 H05 四次点击中，三条 REQ 的编号、原文和来源引用保持一致；四次操作与观察完整保留。正式材料未变时只进行一次正式要求提取；修改任务目标或产品要求后重新提取，并继续通过原文引用校验。 |
| 2 | 检查计划按唯一 `ref` 分组，同一编号携带已有覆盖清单；按新证据涉及的任务与覆盖项更新。 | 每一轮规划中每个编号只进入一个输入分组。初始 35 个编号仍完整覆盖；第二轮分组不因旧覆盖项展开而增加重复编号。保留所有必需检查、覆盖上限、状态及对象引用验证；用回放比较新增、更新和保留的覆盖单元，不直接删除旧覆盖结果。 |
| 3 | 按操作类型压缩上下文，并为相同来源、版本与状态建立可追溯的完整内容副本。每次发生记录继续保留证据编号、时间和动作关系。 | 先用第 018 次请求做离线体积对照，以请求字符数减少 30% 为优化目标，再用实际模型用量测量 token 收益。三条正式要求及原文、所有被引用证据和对象都可解析；返回前后时点仍能对应，故意丢失选择的对照版本仍能被检出。 |

这三项保持当前的目标范围、证据核验和授权约束。建议先做缓存与分组，再做请求体积优化，分别用同一批材料对照验证。
