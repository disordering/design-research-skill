# 旧工作台补记回归修复与 H04/H05 复测

本轮恢复了旧工作台的“补记问题”、当前反馈转问题和历史反馈转问题。补记的标题、步骤、证据、来源、首次记录版本与审核理由进入报告正文，同图重评和刷新恢复后继续保留。上传修改稿后，旧补记归入历史及逐条复审表，初始状态为“无法判断”。

修复基线为 `2157483fb33f4248d2548772840dbaea498d58aa`。该版本保留了补记模块与测试，但覆盖了页面入口、渲染和适配器中的接线。本轮按功能片段合并，保留 C 新增的材料登记、会话版本快照、审核必填理由与新版会话入口。

| 检查 | H04 织物工具借用 | H05 修书咨询登记 |
| --- | --- | --- |
| 冻结原题重新操作 | 返回前 16:00 东侧工坊，返回后 10:00 西侧工坊 | 提交前 14:00 二层，回执 09:00 一层 |
| 补记入口 | 从本轮反馈明确保存 | 先提交普通反馈，再从历史反馈明确保存 |
| 普通反馈 | 保存于操作记录 | 独立导出确认尚未生成该问题 |
| 同图重评 | 补记 ID、证据、首次版本、确认状态和理由保留 | 同左 |
| 刷新恢复 | 成功 | 成功 |
| 修改稿边界 | 再上传同一文件，旧补记进入复审表，待核对 | 同左 |
| 导出正文 | 补记出现 1 次 | 补记出现 1 次 |
| 审核事件来源 | `ai_simulation` | `ai_simulation` |
| HTTP 产品接口 | 3 次返回 200 | 4 次返回 200 |

浏览器由 AI 自动操作，H04/H05 使用仓库冻结页面。工作台提交真实 HTTP 表单到本机 FastAPI，模型使用固定 `contract-stub-v1` 响应，以便单独验证页面、适配器、记录与导出。原始接口响应保存在各任务文件夹，补记内容来自本轮页面操作证据。冻结原题没有修改。

前端全套测试 29 项通过，日志见 [前端测试.txt](前端测试.txt)。新增回归覆盖补记经过会话快照后的审核保留、历史隔离、模拟修改稿待核对和 AI 来源。另保留了 C 的审核理由要求，浏览器先尝试无理由确认，页面正确阻止，再填写理由完成确认。

可直接检查 [核对结果.json](核对结果.json)、H04/H05 文件夹中的原题与工作台截图，以及同图重评和修改稿导出的 Markdown。新版协同入口 `session.html` 的检测、修复判定与终期指标由其他测试记录验收，本轮结论对应旧截图工作台的补记链路。

复跑入口为仓库的 `scripts/d_verify_workbench_supplement.py`。安装开发依赖与 Playwright Chromium 后，在仓库根目录运行

```powershell
python scripts/d_verify_workbench_supplement.py
node --test --test-isolation=none frontend/tests/*.test.mjs
```

脚本自动选择本机空闲端口并在结束后关闭服务。脚本重跑更新本文件夹内的运行证据。
