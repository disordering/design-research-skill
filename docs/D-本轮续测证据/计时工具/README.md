# D 体验记录表：草稿恢复计时修复

本轮修复了“关闭草稿后，离开时间继续累计为操作或工具等待”的问题。正式使用入口是 `docs/D-新版真人执行/02-体验者/两轮任务体验记录.html`。

## 修改内容

1. 导出进行中的草稿时，在保存副本中加入暂停时点。当前页面继续正常计时。
2. 载入草稿后保持暂停，并显示“继续任务请点恢复操作”。离开期间计入外部中断，操作时间和工具等待时间分别保留到草稿导出的时点。
3. 旧版进行中草稿使用原有 `exportedAt` 作为暂停点。已结束草稿的事件和秒数保持原样；既有填写内容保留。
4. 旧草稿缺少有效导出时点时，保留已有记录，并自动登记为“计时不完整”。

沿用 `D-human-v2.1` 数据结构和原有五项时长字段，暂停事件继续使用既有 `break` 类型。新增事件的 `source` 字段说明暂停来自草稿存档或恢复。

## 实际验证

执行来源为 **AI 本地浏览器自动操作**。所有体验编号和填写文本均用于程序验收，评分选择“不适用”。浏览器为 Microsoft Edge；直接通过页面按钮导出 JSON，再按事件时间戳独立复算。

同一组 18 项检查在修复前通过 10 项，修复后通过 18 项；第二轮复验结果相同。检查覆盖操作、等待、外部中断、草稿保存、关页恢复、恢复操作、结束后锁定和旧数据兼容。

以下为第二轮的实际读数：

| 场景 | 版本 | 保存时点复算 | 恢复并结束后的记录 | 结果 |
| --- | --- | --- | --- | --- |
| 操作中保存并关页 | 修复前 | 操作 0.193 秒 | 操作 1.874 秒；中断 0 秒 | 离开时间进入操作时长 |
| 操作中保存并关页 | 修复后 | 操作 0.189 秒 | 操作 0.189 秒；中断 1.675 秒 | 操作时长保持，离开时间进入中断 |
| 等待中保存并关页 | 修复前 | 等待 0.189 秒 | 等待 1.814 秒；中断 0 秒 | 离开时间进入等待时长 |
| 等待中保存并关页 | 修复后 | 等待 0.189 秒 | 等待 0.189 秒；中断 1.632 秒 | 等待时长保持，离开时间进入中断 |

每次关闭页面后实际等待 1.2 秒再重新打开；表中的中断时间还包含新建页面、导入及点击结束前的操作间隔。
