## 接入方式

`scripts/d_screen_codex_probe.py` 中的测试子类只装配 OCR、UI 和审查客户端，完整继承 `QwenScreenTechnicalReviewer.review()`。原生产提示、结构校验、失败修复、视觉指标、判据筛选和产物生成均按现有方法执行；产品引擎源码、配置文件与密钥均保持原状。

测试端使用已登录 Codex CLI 接收原始消息和图片。操作标签只用于日志目录名，未加入生产消息。审查结束后再次用生产函数重建三阶段消息，与归档输入逐项比对，全部一致。

每次调用保存生产消息、实际输入、CLI 原始事件、模型原答、调用参数、线程 ID 和耗时。`调用记录.json` 的输入摘要对应提交给 CLI 的 UTF-8 文本；磁盘文本使用 Windows 行尾，校验时按文本规范化换行。`留档校验.json` 同时保存磁盘文件摘要。

在已有 Python 依赖及已登录 Codex CLI 的环境中，从仓库根目录运行：

```powershell
python scripts/d_screen_codex_probe.py --name 新的批次名 --model gpt-6-astra --max-calls 4
```

脚本拒绝覆盖既有批次。当前单屏实际使用 3 次调用；此次独立补测已完成。
