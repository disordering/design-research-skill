# 两条源码线索的浏览器复核

**W03 原样本。两个不同的报修请求都要重试一次，得到同一个工单号。** 在两个全新的浏览器上下文中，一个提交“工科楼 C-301／投影仪”，另一个提交“工作室 D-405／打印机”。两次首次提交都显示“网络暂不可用，内容已保留”，再次提交后都显示“工单号 M-318／待派单”。回执各自保留了正确的房间和设备。这四次按钮提交均未发起网络请求。此演示可用于测试重试与字段保留；用工单号区分多个报修请求时，需要另外提供可生成不同工单号的服务。

**W04 原样本。** 当天 14:00 陶艺余位为 0，报名提示满员；16:00 篆刻余位为 2，可以报名。这个库存组合只够实测一场成功报名。

**W04 库存实验。同一会话在两个不同时段都有空位时，第二次报名仍要求先取消第一场。** 实验只在浏览器收到的 W04 脚本中把 14:00 陶艺余位由 0 改为 1，仓库原样本文件的哈希保持一致。两个全新会话分别先报陶艺和先报篆刻。第二场尚余 2 个或 1 个名额，均提示“请先取消已有报名”。刷新后进入“我的报名”，均保留第一场。需求只限制同一时段，本地页面把限制扩大到了不同时段；缺陷范围是本地样本在双时段均有余位时的分支。
