# 感知、统计与语义分析链

日期：2026-11-02
适用：协同交互评审会话（A `0.2-method-draft`）

## 当前不是纯提示词

当前会话评审链是：

```text
网站 / Figma / 文档
  -> 工具适配与原始证据保存
  -> Figma 文本节点、逐屏图片、连线和 DOM 控件
  -> 每个完整界面独立执行 OCR、UI 元素、视觉统计和屏内规则审查
  -> 确定性视觉指标
  -> 通用视觉模型读取画面与材料
  -> T03 材料理解、T04 适用性规划、T06 语义判断
  -> 程序校验引用、状态、冲突和目标汇总
  -> 人审报告 + 审计报告 + 原始证据包
```

模型参与语义理解、判据适用、问题解释和严重度理由；程序参与证据获取、视觉测量、结构校验、聚合、去重、版本和报告生成。

## 已接回旧版的确定性能力

`engine/session_perception.py` 现在为每张有效截图生成：

- 全局视觉指标：亮度分位数、亮度对比、平均饱和度、高饱和面积、边缘密度、高频细节、调色板熵、负空间代理；
- 结构元素：Figma 元数据或浏览器 DOM 控件；
- 文本块：Figma 可见文本节点直接读取；浏览器和图片在没有专用 OCR 时保留限制；
- 流程连线：识别 Figma vector/connector 节点，保存节点号、轴向、绝对位置和邻近画板；
- 可读性指标：文本块数、估计字高、低对比候选、小字候选；
- 密度指标：元素数、可交互元素数、交互覆盖率、文本覆盖率；
- 风格指标：同类控件饱和度/对比离散度；
- 显著性代理：基于面积、位置、对比度、边缘和饱和度，不冒充真实用户注意力；
- 元素框叠加图、显著性叠加图，以及单独标出连线和邻接画板的流程叠加图。

这些结果保存在证据的 `analysis`、`analysis_artifact_id` 和 `overlay_artifact_ids`，并进入后续模型上下文与报告包。`source_modalities` 会区分文本元数据、局部界面截图、截图像素和连线几何，避免把“读到大图”写成“逐屏看过”。

连线的确定性提取只证明画布上存在一条线和它覆盖了哪个画板；箭头方向、跳转条件、是说明指向还是操作结果，仍需模型结合画面、`inspection_targets` 和文字说明判断。程序不根据 `Arrow 1` 这样的节点名称直接断言交互。

## 整体流程与单屏技术审查

会话层现在分成两条互补路线：

- **跨界面路线**：页面状态、箭头/邻接画板、流程连续性、同一功能在不同屏幕之间的状态变化、目标/要求一致性；
- **单屏路线**：每个完整局部界面独立执行 OCR、GUI 元素识别、可读性、密度、层级、风格、显著性代理和本屏规则审查。

单屏结果保存在 `SessionSnapshot.screen_reviews`。OCR、UI 元素、指标、叠加图和屏内规则结果都有独立 artifact；屏内候选问题不会冒充跨屏流程结论。模型上下文会同时收到两层结果，报告也分节展示。

## 与旧单图链路的关系

旧 `engine/staged.py` 和 `engine/advanced.py` 仍保留 OCR、UI 元素、判据相关性、指标和叙事阶段。新会话层直接复用了 `engine/cv_metrics.py` 的确定性计算，并将 Figma 节点/DOM 控件转换为统一元素结构。

尚未迁移的部分：

- 对没有 Figma 文本或 DOM 的原始截图，尚未默认调用专用 OCR/GUI 感知模型；
- 判据相关性向量/重排尚未作为独立分项进入会话报告；
- 视觉焦点仍是代理指标，不是真实眼动或用户注意力；
- 旧版单图报告的完整目标分解/相关性审计仍走旧路径。

## 现场读取与可复现快照

后端有两条 Figma 读取路径：

1. **现场读取。** 后端直接连接桌面 MCP；桌面 MCP 只返回当前激活标签页中的节点，因此目标文件未激活时会在元数据阶段明确失败。
2. **可复现快照。** 先用同一 Figma MCP 以 `fileKey + nodeId` 读取元数据，并逐节点保存截图；会话随后通过 `figma_snapshot_id` 回放。快照清单记录文件键、抓取时间和节点尺寸，证据定位标为 `verified_snapshot`，不会冒充现场连接。

快照路径默认是 `out/figma-snapshots/`，可用 `tools.figma_mcp.snapshot_root` 或 `REVIEW_FIGMA_SNAPSHOT_ROOT` 修改。完整会话仍会重跑 T03、T04、T06、T07，不复用旧报告判断。

## 旧证据处理

感知模块接入前的旧会话没有直接保存归一化元素坐标，但完整 Figma MCP 原始元数据仍在。补算时可以按原始父子层级恢复绝对坐标，再对同一张旧截图计算元素、OCR、可读性、密度、风格和显著性代理。吴山石会话 v10 已恢复：

- 8 张截图的分析附件；
- 16 个结构元素；
- 63 个 OCR 文本块；
- 元素框与显著性叠加图。

如果原始元数据本身只有一个图片节点，不能从节点名恢复图片中的控件和文字；这类局部截图只计算全局视觉指标。长流程总图的缩放限制会单独标记，不能把小字候选直接当成可读性缺陷。
