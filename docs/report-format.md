## 报告包结构

```text
report-package-vN/
├── report-showcase.md      # 人审主报告
├── report-summary.md       # 简洁摘要
├── report-details.md       # 完整逐步审计报告
├── report.json             # 完整结构化报告
├── process.json            # T01–T10 输入、输出与模型调用
├── checks.json             # 逐项计划、判断、证据链
├── evidence.json           # 全部有效证据及使用位置
├── findings.json           # 经核验发现及证据链
├── stages/T01.json ... T10.json
├── method/                 # 本轮实际方法文件
├── raw/                    # 模型原始响应
├── artifacts/              # 画面、原文和用户原文件
├── manifest.json
└── SHA256SUMS.txt
```

## 人审与审计分层

`report-showcase.md` 面向设计师、策划和负责人：

- 第一屏给出范围、结论、能判断与不能判断的边界；
- 只展开正式目标/要求、关键发现、主要缺口和可读证据；
- 使用“符合（设计层面）/证据不足/待澄清”等中文状态；
- 使用 `EV01` 等短别名，完整 ID 映射附在证据链后；
- 45 项检查收在可折叠摘要，避免淹没关键结论。

`report-summary.md` 是更短的一页结论和缺口表。`report-details.md` 面向复核和开发联调，保留全部阶段、45 项检查、模型调用和原始响应索引。二者都由同一 `structured_report` 生成，不接受模型另行改写统计。

`GET /export` 默认返回人审版；`format=summary` 返回摘要，`format=audit` 返回审计版。`report.json` 始终保存机器字段。

## 证据链

每个检查项必须同时回答：

1. 计划输入：适用性、对象、来源、计划证据和缺项；
2. 执行输入：本轮实际接收的图片、文本和检查编号；
3. 模型输出：校验后的判断、理由和引用；
4. 程序校验：引用是否属于当前有效证据、必要证据类型是否满足；
5. 最终发现：四段式、严重度、人工审核状态和核验调用；
6. 原始材料：证据 ID、来源版本、定位、画面/原文和方法文件。

模型原始响应保存在 `raw/`，不把摘要或后处理文本冒充原始输出。测试夹具、模型调用、人工决定和历史复审分别标记。

视觉证据还会保存 `analysis_artifact_id`、`overlay_artifact_ids` 和 `analysis` 摘要。分析 JSON 包含 `cv-metrics-v1` 的全局视觉、可读性、密度、风格和显著性代理；新截图还会记录 `source_modalities`、是否为局部界面、直接读取的文本节点数，以及箭头的节点号、轴向和邻近画板。完整局部界面另有 `screen_reviews`：每屏独立保存 OCR、UI 元素、指标、叠加图、规则判断和屏内候选问题。人审稿分别展示逐屏技术审查、界面预览和连线标注，不能把流程总图说成逐屏看过。旧会话若没有可归一化的元素绝对坐标，只计算全局指标，并在人审稿中注明，不补造框或排名。

人审 Markdown 中的关键证据图直接引用报告包内真实存在的 PNG 文件，旁边保留原图链接和证据别名；纯 artifact ID 只用于审计索引，不作为给人阅读时的唯一入口。不使用 `data:image/...;base64`，因为部分 Markdown 渲染器会把它显示成一大段文本。

## Figma 原生报告

每次生成报告包时同时输出：

- `figma-report-plan.json`：机器可读的报告区块、逐屏状态、证据缺口和标注坐标；
- `figma-report-plugin.js`：可由 Figma MCP 执行的发布脚本。

Figma 发布遵循“原稿不动、副本标注”的原则：先复制交互案，再建立独立透明标注层。红色表示通过核验的候选问题，黄色表示待补证据或业务确认；报告画板放在标注副本下方。标注与报告都返回节点 ID，便于复核和后续更新。

报告器启用前产生的旧会话没有保存完整模型输入。此类记录会明确标为“原始输入未保存，索引由输出和当前状态后补重建”，不能与启用后的真实输入日志混为一谈。新运行会把调用 ID、阶段、有效来源/证据、图像证据、检查编号、校验后输出和原始响应一次写入。人审版不会把后补索引写成原始输入。

## 与旧交付报告的关系

格式沿用 `deliverables/2026-10-21-character-trial` 的可复核思路：阶段表、阶段输入/输出、原始响应、结构化报告、证据索引和校验值。区别是当前版本还必须表示多材料、多页面、会话变更和 T01–T10 状态，不能重新压回单张截图的报告结构。
