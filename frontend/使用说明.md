# 使用说明

## 1. 放到哪里

解压后，将frontend完整文件夹放到小组仓库根目录。目录结构应为：

```text
仓库根目录/
  engine/
  requirements-session.txt
  判据库_v1.json
  方法专家开发交付-v0.2/
  frontend/
    dist/session.html
    server.mjs
    启动交互界面.cmd
    启动新版后端.ps1
```

ZIP不是整个项目，不包含B后端。若仓库已有frontend，先用Git分支或另存备份检查差异，再合入；不要覆盖自己的未提交修改。

## 2. 首次准备后端

本项目本机验证环境为Windows、Python3.12.10、Node.js24.22.1；启动自检要求Python3.11或以上。以下命令在仓库根目录执行，不是在frontend目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-session.txt
```

网站/原型取证还需要：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

不要将别人的.venv复制过来。安装下载失败时，应检查自己的网络和代理，不要改动系统证书设置。

## 3. 配置自己的模型

若根目录已有.env或config/reviewer.toml，先检查现有内容，不要直接覆盖。仅在没有本机配置时，将frontend/model.env.example复制为根目录.env，将frontend/reviewer.generic.example.toml复制为config/reviewer.toml。

在.env填写：

```dotenv
REVIEW_PROVIDER=generic
REVIEW_BASE_URL=https://你的兼容服务地址/v1
REVIEW_MODEL=你的视觉模型名称
REVIEW_API_KEY=仅在本机填写
REVIEW_TIMEOUT_SECONDS=90
REVIEW_MAX_RETRIES=1
```

程序会在Base URL后追加/chat/completions，不要重复填写完整/chat/completions路径。在reviewer.toml的[screen_review]中，将三个YOUR_VISION_MODEL都改为同一已获准的视觉模型名。该模板禁用了未配置的qwen/deepseek官方账户，避免与generic混用。

API服务必须支持图像输入及OpenAI兼容的聊天接口。作者本机使用过qwen3.8-flash，但此次测试发现复杂计划输出不稳定，不承诺更换Key即可完整运行。

[providers.generic]默认设置8192输出tokens。只有使用C的backend-launch.py启动时，显式配置的session_enable_thinking才会被传入模型；模板默认不发送此参数。对于已验证支持该参数的qwen3.8-flash兼容服务，可取消注释session_enable_thinking=false。其他模型可能不支持，不要盲目照搬。

如需代理，在.env配置自己电脑的HTTP_PROXY/HTTPS_PROXY；不要复制他人的端口。Figma还需在本机配置并启用对应MCP及权限，仅安装Python库不代表Figma已可用。

配置后，从仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe frontend/check-setup.py
.\.venv\Scripts\python.exe -m engine validate-config
```

自检不调用付费模型；通过自检不代表Key、网络、模型质量均已验证。

## 4. 启动两个服务

后端：右键frontend/启动新版后端.ps1，选择使用PowerShell运行；或在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\frontend\启动新版后端.ps1
```

再双击frontend/启动交互界面.cmd，打开http://127.0.0.1:4173/session.html。前端不需要npm install。若8000或4173端口已被占用，先核对旧服务并正常停止，不要重复启动多个后端。

默认使用原版engine；本包不携带作者本机的临时引擎副本。执行切换引擎.ps1 -Mode copy之前，必须已经存在有效的out/b-engine-copy；脚本不会下载或生成副本。

## 5. 使用工作台

1. 点击检查后端能力。配置可见不等于模型效果已验证。
2. 先填写审核者，再登记材料；选择材料类型、角色、文件、标题及版本，点击加入待提交材料。
3. 填写评审委托，按需提供原始设计目的、目标用户及模型名。默认每轮20次调用、600秒；保持普通交互关闭，除非确实要执行任务内操作。
4. 创建会话；未勾选立即运行时，再点击开始。开始、回答、补充和复审可能调用模型并产生费用。
5. 查看真实检查数、问题和限制。T09、completed或生成ZIP都不代表完整审查通过。执行覆盖包含证据不足的已执行判断，不是质量通过率。
6. 回答待答问题。仅当存在有效发现时，才能确认/驳回发现并填写理由；不能凭空制造问题来测试通过。
7. 有真实新版时，登记恰好一项新版材料，选择对应旧材料后替换并复审。原图重传不代表问题已修复。
8. 选择报告版本查看历史只读结果；通过人审稿、摘要、审计稿、JSON、ZIP交付。后端本机数据库保存记录，会话ID不能跨电脑直接恢复。

## 6. 已知卡点

当前完整审查仍未验收，详见当前情况.md。模型可能返回漏项、无效编号、错误枚举或空数组，触发校验与重试；反复重跑或增加调用上限可能增加费用，不能据此保证解决。

## 7. 如何放到GitHub

将frontend文件夹合入小组仓库自己的工作分支，检查GitHub Desktop Changes仅含拟提交文件，再Commit和Push。上传后，D仍需准备自己的后端环境、Key和材料权限。GitHub仓库存储源码，不自动启动Python及Node服务。

本机产生的Key、.env、reviewer.toml、.venv、out和用户资料不属于交付源码，禁止放进提交。首次交付包的文件清单与SHA-256见包根目录交付清单.json。
